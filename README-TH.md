# PaiBaekPea — ชุดอัปเดตแดชบอร์ดแอดมิน

ชุดนี้ใช้ต่อกับโปรเจกต์ PHP/MySQL เดิมของคุณ ไม่ใช่เว็บไซต์ทั้งชุด
อ้างอิงโครงสร้างฐานข้อมูลล่าสุดที่มี role, account_status, moderation_status และ admin_logs แล้ว
ต้องมี PHP 8.0 ขึ้นไป พร้อม mysqli/mysqlnd และ mbstring ใช้ฐานข้อมูล MySQL/MariaDB เดิม

## ติดตั้งตามลำดับ

1. สำรองโฟลเดอร์เว็บเดิมและ Export ฐานข้อมูลปัจจุบันเก็บไว้ก่อน
2. เปิด phpMyAdmin แล้วคลิกฐานข้อมูลที่เว็บไซต์ใช้อยู่ เช่น `paibaekpea_db`
3. เลือก Import แล้วนำเข้า **database/admin_upgrade.sql** จาก ZIP นี้
   - เพิ่มตาราง admin_settings, analytics_visits, analytics_events และ reports
   - ไม่ใช้ schema.sql เก่า ไม่ต้องสร้างฐานข้อมูลใหม่ และไม่มีคำสั่งลบข้อมูลเดิม
   - นำเข้าไฟล์นี้ซ้ำได้เมื่อโครงสร้างตารางยังเป็นรุ่นนี้
4. คัดลอกไฟล์จากชุดนี้ลงในโฟลเดอร์โปรเจกต์เดิมโดยรักษาตำแหน่งโฟลเดอร์:
   - ไฟล์ใน `admin/` → โฟลเดอร์ `admin/` ของเว็บเดิม
   - ไฟล์ใน `includes/` → โฟลเดอร์ `includes/` ของเว็บเดิม
   - ไฟล์ PHP นอกโฟลเดอร์ → ตำแหน่งรากของเว็บเดิม ซึ่งมี `db.php` อยู่
   - รวมไฟล์และเขียนทับเฉพาะไฟล์ชื่อซ้ำ **อย่าลบหรือแทนที่ทั้งโฟลเดอร์**
   - บน Mac ให้เปิดโฟลเดอร์ต้นทาง แล้วเลือกไฟล์ข้างในไปวางในโฟลเดอร์ปลายทางทีละโฟลเดอร์ เพื่อไม่ให้ Finder ลบไฟล์เดิมที่ไม่มีใน ZIP นี้
5. ใช้ `db.php`, `admin/login.php`, `admin/auth.php`, `admin/logout.php` เดิมที่เข้าสู่ระบบได้แล้ว ไม่ต้องแก้ข้อมูลล็อกอิน
6. เปิดหน้าแอดมินเดิม เช่น `http://localhost/PaiBaekPea/admin/index.php` โดยปรับชื่อโฟลเดอร์/พอร์ตให้ตรงกับเครื่องคุณ แล้วรีเฟรชหน้า

ไม่มีโฟลเดอร์รูป วิดีโอ assets หรือ style.css ในชุดนี้ เพราะใช้ไฟล์เดิมของเว็บไซต์
ไฟล์ `login.php` ที่รากของ ZIP เป็นหน้าเข้าสู่ระบบสมาชิก ซึ่งเพิ่มการตรวจบัญชีถูกระงับ ไม่ใช่ `admin/login.php`
ถ้าคุณแก้ไฟล์หน้าเว็บเพิ่มเติมหลังจากชุดที่ส่งมา ให้เก็บสำเนาไว้และเทียบการเปลี่ยนแปลงก่อนเขียนทับ

เมนูจัดการ:

- **สมาชิก**: ค้นหา เปิดโปรไฟล์ ระงับ/คืนสถานะบัญชีทั่วไปพร้อมเหตุผล ไม่เปลี่ยนสถานะบัญชีแอดมินจากหน้านี้
- **โพสต์ทริป**: ค้นหา กรองสถานะ อ่านโพสต์สาธารณะ ซ่อน/คืนสถานะพร้อมเหตุผล
- **หมวดหมู่**: เพิ่มและแก้ไขชื่อ โดยโพสต์เดิมยังใช้รหัสหมวดหมู่เดิม ไม่มีปุ่มลบหมวดหมู่
- **รายงานปัญหา**: เปิดทริป/โปรไฟล์ที่ถูกรายงาน เปลี่ยนสถานะ และบันทึกผลตรวจสอบ สมาชิกส่งรายงานผ่านหน้าทริปหรือโปรไฟล์ได้
- **ประวัติการจัดการ**: แสดงผู้ดำเนินการ เวลา รายการ สถานะก่อน–หลัง และเหตุผล

การปิดรายงานเป็น “ดำเนินการแล้ว” ไม่ได้ซ่อนโพสต์หรือระงับสมาชิกโดยอัตโนมัติ ให้ดำเนินการในเมนูที่เกี่ยวข้องก่อน แล้วบันทึกผลในรายงาน

## วิธีอ่านตัวเลข

- สถิติผู้เข้าชมเริ่มเก็บหลังติดตั้งและมีการเปิดหน้าเว็บ ไม่มีสถิติย้อนหลังที่ไม่เคยเก็บ
- ผู้เข้าชมไม่ซ้ำแยกด้วยรหัสสุ่มในคุกกี้ เก็บค่าแฮชลงฐานข้อมูล ไม่เก็บ IP ในระบบนี้ คนเดียวหลายอุปกรณ์/ลบคุกกี้อาจถูกนับเพิ่ม
- รอบเข้าชมใหม่เกิดเมื่อเว้นการใช้งานอย่างน้อย 30 นาที หรือเซสชันเดิมสิ้นสุด รอบที่ข้ามวันอาจปรากฏในทั้งสองวันที่มีกิจกรรม
- จำนวนหน้ารวมการเปิดซ้ำเฉพาะหน้า PHP ที่ติดตั้งตัวเก็บสถิติ ไม่รวมรูป ไฟล์วิดีโอ API และคำขอ POST
- สมาชิกที่ใช้งานหมายถึงบัญชีสมาชิกที่เปิดหน้าที่เก็บสถิติในช่วงนั้น ไม่ใช่จำนวนคนออนไลน์ขณะนี้
- ไม่นับบัญชีที่มี role=admin และบอตที่ตรวจพบจาก User-Agent จึงควรใช้เบราว์เซอร์ส่วนตัวแบบไม่ล็อกอินแอดมินในการทดลองยอดเข้าชม
- สมาชิกทั้งหมดไม่นับบัญชีแอดมิน จำนวนโพสต์ใหม่รวมสาธารณะ ส่วนตัว และโพสต์ที่ถูกซ่อน โดยแสดงเฉพาะยอดรวม
- กราฟผู้เข้าชมไม่ซ้ำรายวัน/เดือนนำมาบวกกันอาจมากกว่ายอดไม่ซ้ำทั้งช่วง
- อันดับพื้นที่ใช้โพสต์สาธารณะที่ไม่ถูกซ่อนและสร้างในช่วงที่เลือกเป็นฐาน หนึ่งทริปหลายพื้นที่ทำให้ผลรวมเปอร์เซ็นต์เกิน 100% ได้
- ยอดบันทึกนับรายการ bookmark ที่สร้างในช่วงนั้นและยังไม่ถูกยกเลิก ไม่ใช่ประวัติการกดทั้งหมด
- สมาชิกทั้งหมด รายงานค้าง และพื้นที่รูปเป็นยอดปัจจุบัน ไม่เปลี่ยนตามช่วงวันที่ ข้อมูลสถานะโพสต์ใช้สถานะปัจจุบัน
- เวลาแสดงผลใช้ Asia/Bangkok; ภาพรวมพื้นที่นับไฟล์ระดับบนสุดใน UPLOAD_DIR ตามระบบอัปโหลดเดิม ไม่ลบไฟล์อัตโนมัติ
- ไม่มีนโยบายลบสถิติอัตโนมัติในรุ่นนี้ คุกกี้ผู้เข้าชมมีอายุ 1 ปี

## สิทธิ์ที่คงไว้

ทริปส่วนตัวอ่านและแก้ไขได้เฉพาะเจ้าของ แอดมินไม่สามารถเปิดทริปส่วนตัวของสมาชิกอื่น
ทริปสาธารณะที่ถูกซ่อนอ่านได้เฉพาะเจ้าของและแอดมินที่เข้าสู่ระบบผ่านหน้าแอดมินแล้ว
รูปปกและรูปสถานที่ตรวจสิทธิ์เช่นเดียวกัน รายการสาธารณะ/บุ๊กมาร์กไม่แสดงโพสต์ที่ถูกซ่อน
บัญชีที่ถูกระงับจะถูกตรวจใหม่ในคำขอถัดไป แม้เคยล็อกอินค้างไว้
การเปลี่ยนสถานะของแอดมินใช้ POST, CSRF, ตรวจสิทธิ์ซ้ำ และบันทึกประวัติในธุรกรรมเดียวกับการเปลี่ยนข้อมูล

## ทดลองหลังติดตั้ง

1. ล็อกอินแอดมิน เปิดทุกเมนู แล้วทดลองเปลี่ยนช่วงวันที่
2. เปิดหน้าเว็บจากหน้าต่างส่วนตัวที่ไม่ได้ล็อกอิน เปิดสองหน้า แล้วกลับมารีเฟรชแดชบอร์ด: ควรมีผู้เข้าชมหนึ่งรหัสและสองหน้าที่เปิด
3. สร้างโพสต์ทดสอบแบบสาธารณะ ซ่อนด้วยแอดมิน แล้วดูจากบัญชีอื่นและลิงก์รูปโดยตรง: ต้องเข้าไม่ได้; เจ้าของและแอดมินยังตรวจโพสต์ได้
4. คืนสถานะโพสต์ แล้วตรวจว่าแสดงในหน้าสาธารณะอีกครั้ง
5. ระงับบัญชีสมาชิกทดสอบที่ล็อกอินค้างไว้ แล้วให้บัญชีนั้นเปิดหน้าใหม่/ส่งแบบฟอร์ม: ต้องไม่สามารถทำรายการในฐานะสมาชิกได้ จากนั้นคืนสถานะ
6. เพิ่มและแก้ชื่อหมวดหมู่ทดสอบ แล้วตรวจว่าฟอร์มสร้างทริปเห็นชื่อใหม่
7. ใช้สมาชิกอีกบัญชีรายงานโพสต์ทดสอบ ตรวจรายงานในแอดมิน บันทึกผล และเปิดประวัติการจัดการ
8. ทดลองลิงก์ทริปส่วนตัวของบัญชีอื่นจากแอดมิน: ต้องเปิดไม่ได้

## ถ้าพบปัญหา

- “ยังไม่ได้ติดตั้งตารางใหม่”: Import admin_upgrade.sql ลงฐานข้อมูลเดียวกับที่ db.php ใช้
- “Unknown column” ในตาราง users/trips/admin_logs: ตรวจว่าฐานข้อมูลตรงกับโครงสร้างล่าสุดที่ส่งมา ไม่ใช่ schema.sql เก่า ห้ามนำ schema เก่าทับข้อมูลปัจจุบัน
- “Cannot add foreign key constraint” ตอน Import: ตรวจว่าตาราง users และ trips เป็น InnoDB และ user_id/trip_id เป็น INT แบบ signed ตามโครงสร้างล่าสุด
- “อ่านโฟลเดอร์อัปโหลดไม่ได้”: ตรวจ UPLOAD_DIR ใน includes/init.php ให้ตรงโฟลเดอร์รูปเดิม และให้ PHP อ่านได้
- สถิติยังเป็นศูนย์: ทดลองผ่านหน้าต่างส่วนตัวที่ไม่ได้ล็อกอินแอดมิน และตรวจ PHP error log ถ้ายังไม่มีข้อมูล
- หน้าว่างหรือ HTTP 500: ดู PHP/Apache error log และส่งข้อความผิดพลาดพร้อมชื่อไฟล์และบรรทัด ไม่ต้องส่งรหัสผ่านฐานข้อมูล

ถ้าต้องย้อนกลับ ให้คืนไฟล์จากสำเนาก่อนติดตั้ง ตารางใหม่สามารถเก็บไว้ก่อนได้โดยไม่ต้องลบข้อมูล
